真实单价 · 卡型状态

产品灵魂：分母越大，单价越低
realUnitCostnumber | null
count > 0
　? round(总价 ÷ count)
　: null
真实单次成本。每打一次 count+1，单价下降。
未打卡（除零）→ null，UI 显「—」破折号，绝不显天价
¥2000 ÷ 8 次 = ¥250 / 次
checkInCountnumber
不限次: 有效条数
有限次: min(条数, 总次数)
已打卡次数，公式的分母。预处理已封顶。
打了 45 次的 40 节课包 → 40
remainingTimesnumber | null
有限次: max(0, 总次数 − count)
不限次: null
课包剩余可用次数。不限次卡没有终点，恒 null。
40 节用 10 次 → 剩 30
fullboolean
有限次: count ≥ 总次数
不限次: false
打满标志。UI 据此禁用打卡按钮、冻结最终单价。
打满后禁止打到第 N+1 次
expiredboolean
dayDiff(today, 有效期) > 0
是否已过有效期。过期后停止预测、引导去复盘。
有效期 2027-01-01，今天 2027-06 → true
2

少样本不预测 · 断卡烧钱

早期不乱跳，断了显代价
enoughSampleboolean
count ≥ 3  且  距购买 ≥ 7 天
样本是否足够预测。不足时 UI 藏大数字、改「再打 N 次」引导，避免单价从天价剧烈跳动吓退用户。
两条件须同时满足，任一不够都算少样本
checkInsToSamplenumber
max(0, 3 − count)
还差几次打卡够样本，喂给「再打 N 次就能算」文案。
已打 2 次 → 还差 1 次
breakDaysnumber | null
today − max(所有打卡日)
距最后一次打卡的天数，负反馈的输入。0=今天打过。
从未打卡 → null（不是断卡，是还没开始）
最后打卡 02-01，今天 02-17 → 16 天
dailyBurnnumber
max(1, ceil(总价 ÷ 有效期总天数))
按有效期均摊的每日成本。年卡课包通用。
有效期非法/≤0 天 → 退化为 max(1, 总价)，不除零
¥2000 ÷ 365 天 → ¥6 / 天
wastedByBreaknumber
breakDays > 0 ? dailyBurn × breakDays : 0
断卡期间「白扔」的钱，扎心档负反馈用。
¥6/天 × 16 天 = ¥96
3

心里价里程碑 · 到期结算

参照线 + 复盘结论
belowExpectedboolean
有心里价 且 单价 ≤ 心里价
单价是否已降到心里价以下（已比心里价划算）。心里价是参照线，不是回本终点。
没填心里价 → false（不参照）
checkInsToExpectednumber | null
target = ceil(总价 ÷ 心里价)
有限次再 min(总次数, target)
缺口 = max(0, target − count)
还需打几次单价才低于心里价，喂「再去 N 次」引导。
无心里价/非正 → null；有限次打满都到不了，按打满算
⌈2000/150⌉=14，已打 8 → 还差 6
savedVsExpectednumber | null
(心里价 − 单价) × count
相对心里价省下多少。可为负（仍在亏），复盘总票核心数字。
(150 − 21) × 96 = ¥12,384
无心里价 / 未打卡 → null
wastedUnusednumber
有限次 且 已过期 且 有剩余
　round(剩余次数 ÷ 总次数 × 总价)
课包到期没用完浪费的钱。复盘时的止损提醒。
未过期 → 0（视作还能再用，不提前判死）
剩 30/40 × ¥4080 = ¥3060

feedback · 数字 → 离散枚举

只给枚举，文案/颜色交给 UI（出海与主题的地基）

getBreakLevel(result) · 断卡四档递进（输入 breakDays）

< 3 天
none · 未断卡（今天/近两天打过，从未打卡也算 none）
3–6 天
mild 温和 · 好几天没见啦，今天动一动？
7–14 天
number 给数字 · 停了一周，单价卡在 ¥X 降不下来
15–20 天
harsh 扎心 · 断卡 N 天，白扔 ¥Y 会籍钱（用 wastedByBreak）
≥ 21 天
stop 止损 · 接受沉没成本、下次别续更省（切语气，防沉没成本陷阱）

getStatus(result) · 总览着色（按优先级判定）

review 待复盘
expired === true
（最高优先，过期即复盘）
burning 在亏
未过期 且 breakLevel ≠ none
（断卡进入负反馈）
active 在用
其余正常态
（在持续打卡）

detectTurningPoint(before, after) · 打卡前后对比，弹什么庆祝（优先级从高到低）

fullPaid · 优先级 1
!before.full && after.full
课包这一打刚好打满
becameGoodDeal · 优先级 2
刚跨过心里价线
!before.below && after.below
bigDrop · 优先级 3
单次降幅 ≥ 60 元
「这一次掉了一大截」
none · 兜底
没跨过任何线，不打扰
为什么 core 只产数字和枚举？ 文案、颜色、动画全部留给 UI 按枚举映射——这正是「出海 i18n（枚举→当地语言）」与「主题切换（枚举→token 色）」的地基，core 与四端 UI 各自独立演化。
两个产品参数尚未经验证、随时可调： 转折大跌阈值 ¥60、断卡止损阈值 21 天。源自原型与 TODO 暂定值。
