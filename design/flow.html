断卡负反馈 · 随天数递进

  • 3–6 天 温和：好几天没见，今天动一动？
  • 7–14 天 给数字：停了一周，单价卡在 ¥X 降不下来
  • 15–20 天 扎心：断卡 N 天 · 白扔 ¥Y 会籍钱
  • 21 天+ 止损：接受沉没成本，下次别续更省（切语气，防沉没成本陷阱 A）

计算边界 · core 全兜底

  • 没打过卡：显破折号，不报天价（除零）
  • 少样本：前 7 天 / 前 3 次不预测，改「再打 N 次」
  • 有限次打满：冻结最终单价，禁止打到第 N+1 次
  • 已过期：停止预测，引导去复盘；未用次数算浪费金额
  • 补卡：只能补「购买日 ~ 今天」之间

核心闭环（先验证这一圈）

  • 初见 → 建卡 → 打卡看单价掉，是第一版必跑通的主线
  • 打卡是循环：每去一次回到灵魂屏，单价再掉一截
  • 粘性来自「单价掉下来」的数据反馈本身，动效只放大它

架构纪律（图里四层的约束）

  • core 纯函数、不碰时间：today 永远作参数传入
  • store 只存原始数据，单价 / 负反馈渲染时实时算，不入库
  • 业务层只调 IStorage，切云端只换实现、调用方零改动
  • 文案走 i18n key、颜色走 token：主题切换与出海的地基
