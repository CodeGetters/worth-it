# 值啦 · 产品方案

> 产品名:值啦 / Worthit（英文项目名候选见下）
> 副标题:你手里的卡,哪张值啦 · Which card is finally paying off?
> Slogan:又去了一次,值啦。 · One more visit. Worth it.

## 一句话定位

值啦是一个**买了卡之后、每次去用就来打卡**的轻量工具。它帮你盯住手里的健身卡、私教课包、瑜伽课、游泳课、医美疗程等按次消费的卡,看着真实单次成本一次次往下掉,督促你别让卡躺死,也帮你看清自己有几张卡、哪张真用得上、哪张办了白办。

核心心智:

> 卡都办了,就别让它躺死。每去一次,这一次实际花的钱就往下掉一截——去得越多越值。

## 为什么这个方向有意思

办卡时算的是"理想单价",但真正决定划不划算的是**你买完之后到底去了几次**。大多数人办完卡就忘,钱白花:

- 健身年卡办了,三个月去两次。
- 私教课包买了 40 节,用了 10 节就过期。
- 瑜伽卡冲动办,办完再没打开过。

值啦把"真实单价"做成一个**每次打卡都在变化的活数字**:

- 你每去一次,分母变大,单价往下掉,肉眼可见地"赚回来"。
- 你断卡不去,单价就卡住降不下来,还在白白烧钱。

这个工具的价值,是把"去用卡"这件反人性的事,变成一个有即时反馈、有爽感、有督促的打卡游戏。



## 适用品类(第一版:只做"按次消费")

第一版只做**按次使用的卡**——因为"打卡看单价掉"的爽感只对"去一次算一次"成立:

- 健身房年卡(不限次)。
- 私教 / 瑜伽 / 普拉提 / 舞蹈课包(有限次)。
- 游泳课、拳击课。
- 医美疗程卡、美容护理卡(按疗程/次数)。

**暂不做**手机套餐、宽带、视频会员、网课等——它们是按月扣费 / 分期 / 涨价模型,不是"去一次掉一次"的打卡模型,与核心爽感冲突,归入后续批次。

## 两种卡型


| 卡型        | 例子      | 特点                     |
| --------- | ------- | ---------------------- |
| **不限次年卡** | 健身年卡    | 没有"用完"的终点,去越多单价越低,一直降  |
| **有限次课包** | 私教 40 节 | 有总次数上限,没用完的次数会随有效期过期作废 |


## MVP 功能

### 1. 添加我的卡

像填一张待开的小票,尽量少填:

- 卡名、总价、卡型(不限次 / 有限次)。
- 有效期(年卡默认"今天+1年",可改)。
- 总次数(仅有限次课包需要)。
- 你心里"一次值多少钱"(可先不填,仅作参照线)。

### 2. 打卡 · 看真实单价往下掉(灵魂)

这是产品的核心屏:

- 超大单价怼脸:**真实单次成本 = 总价 ÷ 你实际去的次数**。
- 每点一次"今天去了,打卡",大数字向下滚动一截。
- 不限次卡没有终点,去越多越便宜;有限次课包打满后冻结最终单价。
- 心里价是一条横向参照线(贵 / 省),不是回本终点。

示例:

> 健身年卡 ¥2000,你去了 8 次,这一次实际花了 ¥250。再去一次,就掉到 ¥222。

### 3. 断卡负反馈 · 督促回来

不去用,单价就卡住降不下来。负反馈随断卡天数递进升级:

- 温和(3-6 天):好几天没见啦,今天动一动?
- 给数字(7-14 天):停了一周,单价卡在 ¥250 降不下来。
- 扎心(15 天+):断卡 16 天,白付了 ¥80 会籍钱。
- 止损(21 天+):也许这卡本就不适合你,接受沉没成本、下次别续更省。

### 4. 多卡总览 · 哪张值、哪张在亏

卡一多,总览最有说服力:

- 所有卡一览:在用(绿)/ 在亏(红)/ 待复盘(灰)。
- 汇总:你总共在这些卡上,是省了还是亏了。
- 一眼看出哪张卡用得值、哪张该止损别续。

### 5. 到期复盘 · 指导下次决策

卡到期给一张"结算总票",用本次真实数据告诉你下次怎么选:

> 这张卡一年去了 96 次,最终每次只花 ¥21,比单次买省下 ¥12,400。你这频率,续年卡比月卡每月省 ¥120,放心续。

## 页面流程

第一版以**打卡为中心**的几屏:

1. 空状态:一张能直接点的示例卡,先尝"单价掉"的甜头。
2. 添加我的卡。
3. 打卡灵魂屏(默认首页,左右滑切多卡)。
4. 断卡负反馈(打开时被动叠加)。
5. 到期复盘。
6. 底部 tab:打卡 / 总览 / 我的。

## 视觉设计方向

`design/` 下沉淀了三套设计探索,各自带 `README.md`(设计系统总结)和 `reference/`(可跑的 HTML 原型 + critique 评分)。三套共享同一设计 DNA,差异在底色与气质,**最终视觉风格仍待选定**。

### 三稿共识(设计 DNA)

无论哪套都遵守:

- **卡片是主角,钱包式呈现**:首页像 Apple Wallet,管理一张张「已花钱、要被用回来的卡」,不是账单列表。
- **真实单次成本是最高层级数字**:比卡名、总价、剩余次数都大,第一眼就看到「这次花了多少、还能降到多少」。
- **打卡 = 即时反馈**:每次确认使用,大数字滚动下降、进度推进,看到「又把成本打低了一截」。
- **绿色只服务「成本下降」**:不做大面积装饰色,避免变成理财产品 / 廉价进度条;拒绝积分、等级、金币抽奖等廉价游戏化。
- **动效克制**:只动 `transform / opacity`,不晃动、不夸张弹跳,保留 `prefers-reduced-motion` 兜底。

## 关键计算逻辑

### 真实单次成本(核心)

总价 ÷ 你实际打卡的次数。每打一次,分母 +1,单价下降。

### 不限次卡

没有"用完"的终点,去越多单价越低。心里价仅作参照线。

### 有限次课包

- 真实单价 = 总价 ÷ 已打卡次数。
- 打满总次数后冻结(不允许打到第 N+1 次)。
- 到期时没用完的次数 = 浪费金额 = 未用次数 ÷ 总次数 × 总价。

### 计算边界兜底

- 没打过卡(除零):不显示天价,显示破折号 + "打第一次卡后开始计算"。
- 少样本不预测:前 7 天 / 前 3 次内不给会乱跳的预测,改为"再打 N 次就能算"。
- 已过期:停止预测,冻结最终单价,引导去到期复盘。
- 补卡越界:只能补"办卡当天 ~ 今天"之间。

## 差异化

### 不是买前的避坑计算器

值啦发生在**付款之后**:卡已经办了,接下来要解决的是"怎么逼自己用回本",而不是"买不买"。

### 不是普通记账工具

记账记录的是花了多少。值啦盯的是**你用了几次、单价掉到多少、还剩多少没用**——它是一个有督促、有爽感的打卡器,不是流水账。

### 不做法律 / 消费建议

值啦只如实呈现你自己的打卡数据和由此算出的真实单价,不做任何购买、退款或法律判断。

## 传播钩子

适合小红书、抖音、知乎标题:

- 办了健身年卡,我每天打卡看单价从 ¥2000 掉到 ¥21。
- 这张卡到底值不值?打卡 30 天给你答案。
- 私教课包别一次买太多,看我打卡到一半就过期亏了多少。
- 用打卡治好了我的"办卡就忘"。
- 手里 5 张卡,值啦帮我看哪张在偷偷烧钱。

## 冷启动验证

先做一个网页或小程序,跑通"添加卡 → 打卡 → 单价掉"的核心闭环。

验证方式:

- 看是否有人持续打卡(留存)。
- 看"单价掉"的爽感是否被截图分享。
- 看断卡负反馈能否把人召回。
- 测试到期复盘是否影响下次决策。

## 变现方式(验证出价值后再做)

### 免费

- 基础打卡 + 真实单价计算。

### 会员 / 增值

- 多卡对比("哪种买法最省"工作台)。
- 历史卡归档与跨端同步。
- 分享卡(转折节点生成可保存的海报图)。

### 后续扩展

- 主动推送(断卡 / 快过期提醒)。
- 家庭多人共享卡的打卡。

## 后续需要讨论的问题

- 第一版先只做健身私教,还是按次品类都支持?
- 是否需要主动推送把断卡用户召回,还是只做打开时被动显示?
- 断卡负反馈语气可调到多狠?
- "哪种买法最省"对比功能何时放出入口(目前已做好但隐藏)?
- 多端账号何时打通(微信 + 手机号 → 同一用户)?
